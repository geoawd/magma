# Application Design

## Runtime

This is a static browser application served over HTTP; it has no build step. `index.html` loads core vendor libraries and `js/config-loader.js`. The loader selects a profile, loads the public overlay/terrain fragments when needed, validates `window.CONFIG` through `js/config-validation.js`, and then starts `js/styles.js`. The style loader fetches configured MapLibre styles, merges their vector sources/layers, and starts `js/app.js` as a module. `js/app.js` owns map lifecycle, layer controls, theme switching, search, and result panels. `js/map-feature-query.js` handles rendered-feature discovery, query geometries, and linked-record joins through an injected MapLibre map/config interface. COG ramp, hillshade, and contour controls are built by `js/cog-ramp-controls.js`; `js/cog-overlay-layer-controller.js` initializes configured and restored COG state, adds raster sources and layers when their protocol is ready, and applies opacity changes. Custom COG CRS definitions in `CONFIG.cogProjections` are registered after the protocol loads through `js/cog-projections.js`, preserving lazy loading. JSON-theme popup construction and ArcGIS feature sections are handled by `js/json-theme-popup.js`, which receives its map, theme state, configuration, and cell renderer as dependencies. `js/terra-draw-controller.js` lazily loads the Terra Draw vendor assets, creates its MapLibre control, and positions it beside the location control. Terra Draw is loaded when Advanced mode is enabled, the COG protocol when a COG or terrain source becomes active, and XLSX only when an export is requested. The data catalogue uses the same profile validation and defers the COG protocol until a COG export needs it. `data-catalogue.html` is a standalone catalogue that groups only GeoJSON and COG sources alphabetically, includes every configured terrain COG model (including DSMs and DTMs), and provides expandable metadata records from `CONFIG.layerInfo`/`CONFIG.groupInfo` using `CONFIG.infoFields`. Records load on first expansion. The page also provides source-copy and QGIS `.qlr` downloads without loading the map; GeoJSON exports use configured styles and single-band COG exports use configured class breaks or the configured smooth quantile color ramp. `CONFIG.cogStyleDefaults` sets the default ramp, mode, and quantile stop count for COGs without class breaks.

For first-time setup and user-facing examples of the profile config, PMTiles, GeoJSON, JSON themes, COGs, styling, and projection registration, see [`GETTING-STARTED.md`](../GETTING-STARTED.md). Keep that guide synchronized with configuration/runtime changes and add or revise examples when supported data formats or settings change.

`js/map-layer-visibility.js` owns the shared selected/theme/group visibility rules and their MapLibre side effects. `js/map-theme-controller.js` resolves configured vector, dataset, overlay, and overlay-group membership for the active theme. `js/legend-category-controller.js` applies category filters and coordinates shared isolation/restore behavior for vector and GeoJSON legends. `js/legend-in-view-controller.js` filters legend categories against rendered features, caches field values per update, and responds to map idle, movement, and source-data events. `js/vector-legend-controller.js` builds vector style-layer groups and category controls, records visibility, and registers rendered-feature legend groups. `js/overlay-legend-controller.js` assembles grouped overlay rows and delegates visibility, terrain, GeoJSON, COG, download, and ArcGIS legend behavior to their focused controllers. `js/overlay-visibility-controller.js` coordinates overlay checkbox and theme visibility across GeoJSON classes, COG state, hillshade, contours, and symbology. `js/overlay-download-controller.js` owns download-control markup and binds COG and GeoJSON source-copy and QGIS `.qlr` export actions to their status controls. `js/overlay-row-controls.js` composes standard overlay row tools, legend expanders, extent zoom buttons, info panels, and control panels. `js/geojson-legend-controller.js` builds GeoJSON class legends and their filter, isolation, percentile-sort, geometry-swatch, and in-view state. `js/arcgis-legend-controller.js` loads ArcGIS legends and filters symbols against the current map view using identify requests. `js/box-selection-controller.js` handles mouse, touch, and keyboard box selection and combines vector and ArcGIS query results. `js/data-search-controller.js` filters GeoJSON records and visible PMTiles features, builds searchable layer and field choices, and presents matching results. `js/location-search-controller.js` parses Irish Grid references, resolves place and coordinate searches, manages the result list and map marker, and navigates the map. `js/notification-controller.js` validates configured notification forms, collects a map location, maintains the report preview, and supports copy/email actions. `js/geojson-style-controller.js` owns GeoJSON classification controls and applies or resets session styles using the pure helpers in `js/geojson-classification.js`; configured base styles remain in the overlay data. `js/geojson-layer-controller.js` creates GeoJSON map sources and geometry-specific layers, records original style/filter state, and registers their initial visibility. `js/terrain-models.js` normalizes legacy and multi-model terrain configuration and verifies HTTP byte-range support. `js/terrain-controls.js` owns hillshade and contour control markup, style state, and paint updates; `js/terrain-legend-row.js` builds and binds the DEM selection, zoom, and exaggeration controls in the overlay legend; `js/terrain-runtime-controller.js` switches elevation models and synchronizes 3D terrain with map pitch and controls. `js/cog-contour-source.js` shares the cached COG-to-contour DEM tile adapter and no-data decoding used by terrain and COG overlays; `js/app.js` coordinates contour source and layer lifecycles and the remaining overlay legend rows.

The layers panel starts in standard mode and includes an **Advanced mode** toggle beside **Legend**. Advanced mode reveals the Terra Draw toolbar and enhanced legend settings. **Select by box** is available in both modes. Dataset rows with a supported extent show an explicit zoom-to-extent button beside their layer options; COG extents come from raster metadata, GeoJSON extents from loaded features, and PMTiles vector extents from archive headers. Other overlays can specify WGS84 `bounds` as `[west, south, east, north]`. WMS, imagery, and ArcGIS MapServer overlays omit the button. Selecting a DEM changes the active terrain source without moving the map; use its zoom button to navigate to the selected DEM. Click category checkboxes to toggle individual classes, or use the category isolate control to show only one class; **Restore previous** returns that layer's prior category selection. Set `filterlegend: true` on a GeoJSON overlay, or add its vector style-layer key to the top-level `CONFIG.filterlegend` map, to list only classes with rendered features in the current view; filtering is off by default. This view-based legend remains consistent while isolating a class and after restoring the prior selection. Standard mode keeps COG transparency, source-URL copy, and QGIS `.qlr` download actions available; color ramps, display classifications, and other enhanced layer settings require advanced mode. The QGIS export uses the native GDAL source, EPSG:29902 (overridable with the layer's `qgisCrs` or `projection` config), and the active browser ramp and breaks when available; it falls back to single-band gray if styling cannot be prepared. Turbo is the fallback ramp when no browser ramp is selected. The ArcGIS Pro entry is a disabled placeholder for COG layers. GeoJSON layer controls also provide QGIS vector `.qlr` export and source-URL copy; the export uses the OGR provider, configured CRS, geometry, opacity, and current configured or session classification. The top-right Terra Draw toolbar appears directly below **Find My Location** and includes point, line, polygon, rectangle, circle, freehand, angled rectangle, sensor, sector, select, delete, and download tools.

On mobile, the tools drawer opens at 45% of the viewport height, can be dragged up to 80%, and closes when dragged down below 25%. The **More map tools** menu provides globe and print actions, plus drawing controls in Advanced mode. The Terra Draw script and styles load on demand; the drawing toolbar appears on mobile only while requested from this menu.

## UI Variants

`js/ui-variant.js` runs from `<head>` and sets `data-ui` on `<html>`. The default is `v2`; `?ui=classic` restores the previous layout and `?ui=v2` switches back, and the choice is remembered in `localStorage`. The base styles in `css/app.css` are the classic layout. `css/app-v2.css` loads after it and scopes every rule under `html[data-ui="v2"]`, so removing that attribute value gives the classic UI. `js/theme-preference.js` sets `data-theme` before styles load, initially follows the device color preference, and persists the user's Light or Dark selection across the map viewer and data catalogue. Theme selection is available as side-by-side previews under Information > Theme. `css/app-dark.css` styles the map viewer's interface only; the map canvas, basemap, and dataset colors are not inverted or switched. The catalogue has corresponding dark colors in `css/data-catalogue.css`. `js/app.js` reads the same UI variant flag (`uiV2`) for the few behaviors CSS cannot express.

In v2 the map is full-bleed with a floating tools panel (a floating bottom dock on mobile), shared rounded "chip" styling for map overlays and controls, a centred place search, light legend group headers, and a single legend gutter with fixed tool columns (info, layer tools, zoom to extent from left to right). Share view and Copy tour stop sit with the Report buttons at bottom-right. The desktop rail starts collapsed on a first visit and then remembers its last tool in `localStorage` (`mapviewer.rail.v1`). The results panel is a floating card whose tabs and filter pills are restyled for both JSON themes and vector results. When changing legend or results markup, check both variants. Playwright preseeds `mapviewer.rail.v1` so tests start with the legend open, as a returning visitor would see it.

## Map Notifications

`CONFIG.notifications` defines report types shown as map controls in Advanced mode, in the bottom-right corner above the attribution. Each entry has a unique `id`, button `label`, dialog `title`, optional email `recipient`, optional bold `reminderText`, and `fields` array. The reminder is configured separately for each report type, displayed below the message preview, and is not included in copied or emailed text. Fields support `text`, `email`, `tel`, `number`, `date`, `select`, and `textarea`; select options can be strings or `{ value, label }` objects. Optional field settings include `required`, `min`, `max`, `step`, `placeholder`, and `rows`. Selecting a report type arms point-picking on the map; the generated form includes the Irish Grid reference with six-digit easting and northing, WGS84 coordinates, and a map link. Users can edit the generated message, copy it, or open it in their email client. Report types, reminders, and recipients can be added or changed in the profile config without changing the form implementation.

## SpaceMouse Navigation

Set `CONFIG.spaceMouse.enabled` to `true` to enable the SpaceMouse connection and preferences controls. Set `CONFIG.spaceMouse.advancedModeOnly` to `true` to show them only while Advanced mode is on. In a WebHID-capable browser on a secure context, users can connect a 3Dconnexion device from the connection control; discovery supports current and legacy vendor IDs and generic multi-axis HID collections, and previously authorized devices reconnect automatically. Without WebHID, the controls remain discoverable in Advanced mode, the connection control is disabled, and preferences remain available. Translation axes can be assigned to horizontal pan, vertical pan, zoom, or left unassigned; rotation axes can be assigned to pitch, heading, or left unassigned. The defaults are translation X/Y/Z to horizontal pan/vertical pan/zoom and rotation X/Y/Z to pitch/unassigned/heading. Vertical pan and pitch directions are reversed by default. Multiple inputs assigned to the same action are combined and clamped to the supported range. Both separate translation/rotation reports and combined six-axis reports are supported. `panPixelsPerSecond`, `zoomLevelsPerSecond`, and `rotationDegreesPerSecond` set the default navigation speeds. The preferences dialog provides dropdowns for each axis, speed controls, and independent direction reversal for each action. User preferences are stored separately from map sessions in browser `localStorage`, scoped to the active profile, and can be reset to the configured defaults.

## Session Recovery

The viewer initializes its controls when the map style is ready, without waiting for remote tile sources to finish loading. This lets the app start even when a configured PMTiles archive is unavailable. The viewer autosaves a versioned session snapshot to browser `localStorage`. On a later visit, it offers **Resume** or **Reset app** when a valid snapshot exists. Resume restores the active theme, map view, layer visibility and transparency, per-theme overlay visibility, COG display settings, and terrain settings. The Information panel also supports up to 20 named workspaces; saving an existing name updates it, and workspaces are stored locally per profile. Reset app clears the autosaved session and manually added layers, and clears filter state encoded in the URL hash; named workspaces are preserved. Internal profile state uses separate storage keys; the public profile retains its existing keys. Nothing is sent to a server.

Shared links take precedence over the saved-session prompt. Map-view hashes in `#zoom/latitude/longitude` format initialize the map to that view and drop a location pin; encoded JSON theme links restore their map/filter state without prompting or adding a pin.

## Security and deployment checks

The viewer uses a Content Security Policy in `index.html` that restricts executable scripts, stylesheets, and workers to self-hosted assets, blocks plugins, and permits HTTPS data, image, and font sources so configured services, custom data, and remote legends continue to work. MapLibre workers are self-hosted; `blob:` workers remain enabled for runtime-created workers. WebAssembly compilation (`wasm-unsafe-eval`) is allowed while ordinary JavaScript `eval` remains blocked. Inline styles remain enabled because the app and MapLibre set styles dynamically. Forms are restricted to same-origin submission, and the optional tour video uses YouTube's privacy-enhanced embed origin. The data catalogue has a similarly tightened policy. HTTP connections remain allowed for localhost development and `cog:` for the custom COG protocol. Attribute-derived popup values are escaped, and generated links allow HTTPS or same-origin destinations only. GitHub Pages does not allow this repository to set arbitrary response headers, so controls such as `frame-ancestors` and `X-Content-Type-Options` must be configured at a reverse proxy or other hosting layer if required.

Run `npm test` for configuration, runtime, and startup tests. Run `npx playwright install chromium` once and `npm run test:e2e` for browser coverage. The Pages workflow runs both suites before deployment and on pull requests to `main`.

ArcGIS REST queries cancel superseded requests and cap each request at 500 features. Services that report a transfer limit direct users to zoom in or draw a smaller selection.

## Interactive Tours

`config/tours.js` is loaded independently of the profile config and defines `window.TOURS`. Each tour has a unique `id`, `name`, and `stops` array. Configured tours are selectable in the Information panel, where users can also copy a share link. A URL with `?tour=<id>` starts that configured tour automatically after startup. Each stop can define `title`, `description`, `target` (a UI selector to highlight), `center`, `zoom`, `bearing`, `pitch`, `duration`, and optional boolean `terrain`. Set `terrain: true` or `terrain: false` to enable or disable 3D terrain for that stop; when terrain is specified without a pitch, enabled stops use the configured terrain pitch and disabled stops use a flat pitch. Stops without `terrain` leave the current terrain state unchanged. Optional layer actions are expressed as `layers.show`, `layers.hide`, `layers.overlays`, and `layers.hideOverlays`; overlay IDs use the same IDs as `CONFIG.overlays`. A `theme` selects an existing theme by name or option value. A trusted `popup.html` string and optional `popup.lngLat` can display explanatory HTML, images, or video at a stop. The existing help tour remains available as a fallback.

Set `CONFIG.copytourlocation` to `true` to show the **Copy tour stop** map control in Advanced mode. It copies a paste-ready stop containing the current theme, overlay visibility, camera position, and terrain state; replace its title and description before adding it to `config/tours.js`.

The video-export plugin is intentionally not loaded by default. A future exporter adapter can consume the same stop camera sequence and add the plugin's `VideoExportControl` without changing the map controls or tour schema; this keeps the extra dependency and browser recording permissions opt-in.

## Directory Layout

- `config/config.js`: public profile's `window.CONFIG` for map defaults, vector datasets, basemaps, raster overlays, themes, legend metadata, search, and terrain.
- `config/notifications.js`: public profile's notification types and form fields, exposed to the app through `CONFIG.notifications`.
- `config/config.internal.js`: internal profile's `window.CONFIG`; present only on the internal branch.
- `config/tours.js`: independently loaded `window.TOURS` definitions for interactive tours.
- `js/config-loader.js`: loads the public profile by default, or the internal profile when opened with `?profile=internal`.
- `config/config_geomaterials.js`: `window.GEOMATERIALS_CONFIG` for the JSON-backed Geomaterials theme: data paths, schemas, filters, links, popups, and depth symbology.
- `config/*.json`: MapLibre styles and deployment/link configuration.
- PMTiles archives are optional and configured per vector dataset; no local archive is required by the current public profile.
- `data/geomaterials/*.json`: Geomaterials tables. Each file contains an array at the configured `dataKey`.
- `js/`: startup/style merging and map application behavior.
- `css/app.css`: application and panel styling.

## GeoJSON Attribute Classification

Advanced GeoJSON classification supports quantile ranges, equal intervals, manual numeric breaks, unique values, and Tellus Percentile. Tellus Percentile uses linear interpolation to calculate breaks at the 1st, 2nd, 5th, 10th, 15th, 20th, 25th, 40th, 50th, 60th, 75th, 85th, 90th, 95th, 98th, and 99th percentiles. Its legend shows each class's upper break value to two decimal places beside its percentile rank, and the arrow reverses the displayed order without changing the map colors or class filters. Tied percentile values are combined so the MapLibre step expression remains strictly increasing; constant-valued fields appear as one “All values” class.

## Map Configuration

Edit the profile config to change its map-wide setup: `config/config.js` for public, or `config/config.internal.js` for internal. The internal URL must include `?profile=internal`; omitting the parameter loads the public profile.

Edit `config/notifications.js` to add or change public-profile notification types and form fields. The loader evaluates it before `config/config.js`, which assigns the definitions to `CONFIG.notifications`.

- `datasets` associates a dataset ID and display name with a complete MapLibre style file and PMTiles URL. Keep each dataset's sources, vector layers, paint expressions, and optional `metadata["legend-groups"]` in its configured style file. Layer metadata can set `theme-layer` to give archives with identical source-layer names distinct controls, and `legend-label` for their display names. Data-driven class legend labels can be supplied as layer metadata `legend` with matching `entries` in expression order. `layerDefaults` controls each vector layer's initial visibility in the assembled style, before MapLibre's first render; layers not set to `true` start hidden and can be enabled in the legend.
- `basemaps` describes persistent raster basemaps.
- User-added ArcGIS MapServer feature sublayers are queryable by default. Cached tile-only MapServers remain display-only because they do not expose individual queryable sublayers.
- A GeoJSON overlay uses `geojson: true`, `url`, and optional `projection`, `geometryType` (a legend hint before lazy-loaded data is available), `style` (`color`, `width`, `dasharray`, `radius`, `fill`), `opacity`, `visible`, `minzoom`, `maxzoom`, `attribution`, `legendUrl`, and `info`; see the full example in `config/config.js`. Loaded geometry determines the legend symbol: points use dots, polylines use colored strokes, and polygons use filled swatches like the COG class legend. Polygon features render with a fill layer using `style.fill`, or `style.color` when no fill color is configured; line outlines and points use `style.color`. `style.color` and `style.fill` accept MapLibre `match` expressions for explicit string or numeric classes and `step` expressions for numeric ranges. Add `legend: { title, entries: [{ label, color }, ...] }` to control the Basic-mode legend text and swatches; entries correspond to the classes in the style expression, or provide static symbols when the style has no data-driven expression. A static single-color style without explicit entries automatically displays one non-filterable symbol labeled with the layer name. The legend lists data-driven classes/ranges and allows each category to be toggled. Advanced mode provides an attribute classifier for loaded GeoJSON, with quantile, equal-interval, manual numeric breaks, and unique-values methods. Unique-values classification is disabled above 20 distinct values. Advanced classifications and the reset-to-default action are held in memory for the current page session only. The app creates its empty map source at startup but only fetches the GeoJSON when the layer first becomes effectively visible (enabled in the active theme and not hidden by its group). The data is retained for the page session, so later visibility changes do not refetch it. A failed request shows an error and can be retried by turning the layer off and on. `minzoom` and `maxzoom` limit rendering; they do not defer loading after the layer is enabled.
- Set `styleUrl: 'config/hydrostyle.json'` on a GeoJSON overlay to load its styling from a JSON file. The file must have a `style` object and may include a `legend` object; these are assigned to the overlay, with the external style taking precedence over inline `style` and an external legend replacing inline `legend` when present. The style file loads when its overlay enters the active theme; GeoJSON data remains deferred until the layer is enabled and effectively visible.
- `overlays` describes WMS, ArcGIS MapServer, XYZ raster, and COG layers. Use `group` to organize overlays in the layer panel. Set `queryable: true` on an ArcGIS MapServer overlay to include its configured `layers` in map-click and box-selection queries; only effectively visible queryable overlays are queried, and returned attributes appear in grouped sections of the click popup or results table. Box selection submits its screen rectangle as a polygon so rotated map views retain the selected extent. This does not change raster rendering or make other overlays queryable. ArcGIS legend JSON and `legendUrl` images load only when the overlay enters the active theme, and successful legend/style responses are reused when returning to a theme. Raster tiles still load only while their layer is visible. The config loader applies `encodeURI` once to overlay and terrain COG URLs; supply unencoded paths and avoid pre-encoding percent escapes. Single-band COG color ramps and display classifications are available in advanced mode: continuous styling, smooth 64-stop quantile styling, a percentile-clipped style that stretches the 2nd–98th percentile sample range across the ramp, or configured class breaks. Standard mode retains COG transparency and the source-URL copy action for GIS. Multiband COGs keep their native RGB rendering. COG overlay sources, metadata, and value-range samples are deferred until a COG layer is enabled and effectively visible in the active theme; hidden COG overlays do not trigger source or sampling requests, and sampling stops if a layer is hidden before the range is complete. COG overlays accept `resampling: 'nearest'` or `resampling: 'bilinear'`; the default for color rasters remains nearest. Set optional `legendunits` on a COG overlay to show its units on the left of the legend title, with the ramp name aligned right above the color bar. COG hillshade controls are hidden unless an individual COG has `hillshade_option: true` (the string `'true'` is also accepted); when enabled, hillshade is on by default at 20% strength. COG hillshade relief is automatically scaled from the sampled value range toward a 100-unit range to make low-range rasters visible; the relief exaggeration slider provides a 1–100 nonlinear adjustment. Changing the COG transparency also scales its hillshade strength by the remaining opacity. Quantile stop positions and percentile clipping bounds come from a sample of the lowest-resolution available overview; quantile colors are interpolated into one raster layer to avoid seams between independently masked classes. Configured breaks use each `max` as the inclusive upper bound of a class; values above the last break use the final ramp color. Break labels are optional and appear in the class legend. The color ramp is divided evenly over the resulting classes, and the COG renderer's lookup palette has 4096 stops. For example:

  ```js
  {
    id: 'my_cog',
    name: 'My COG',
    cog: 'https://example.org/data/my-raster.tif',
    legendunits: 'ppm',
    resampling: 'bilinear',
    classes: [
      { max: 50, label: '2nd percentile' },
      { max: 100, label: 'Median' },
      { max: 250, label: '98th percentile' }
    ]
  }
  ```

  Supply the COG as a hosted, browser-accessible Cloud Optimized GeoTIFF URL, and set `classes` on that COG overlay in the relevant `window.CONFIG`. Configure ascending finite `max` values; the first class covers values up to its break and each following class covers values above the previous break through its own break. The legend shows only the configured classes; values above the last break use the final configured class color. Numeric COG legend labels and range endpoints display two decimal places; this is presentation-only and does not round styling or sampling values. Select any available ramp in the layer controls; its colors are distributed across the configured classes, with a matching discrete legend. COGs without `classes` retain the existing display modes. The default ramp is CET rainbow4. The picker also includes 27 continuous/diverging Colorcet `palette_n` ramps; their 256-color data and CC BY 4.0 attribution are in `js/colorcet-ramps.js`.

  While the cursor is over the map, a separate readout above the zoom and coordinate indicators shows sampled values for visible single-band COGs, one `layer name: value` per line. Configured `legendunits` are appended to each value.

- Set `contour_option: true` on a single-band COG overlay to generate contours while that COG is enabled. Configure `contour_intervals: { minor, major }` and `contour_colors: { minor, major }`; intervals use the COG's value units and default to 10 and 50. Advanced COG controls can toggle contours and adjust intervals/colors at runtime. COG contours are created lazily with their parent layer.
- `terrain.models` lists the selectable DEMs used for 3D terrain and hillshade. Switching models requires the server to honor HTTP byte-range requests; models that would trigger a full-file download are rejected. A successful switch zooms to the geographic extent reported by the DEM's COG metadata.
- `themes` controls layer visibility. `layers` accepts source-layer names or `theme-layer` keys from the style; `datasets` expands to the layer keys from a configured dataset; `overlays` accepts overlay IDs; `groups` accepts style legend-group names, overlay-group names, or another named theme. Names are matched exactly and are case-sensitive. A theme with no selection properties allows all configured layers; specify at least one selection property to turn unlisted layers off. On first entry to a theme with multiple overlay groups, only the first layer of its first group is enabled by default. The app remembers overlay visibility separately for each theme while switching between them. When a group containing multiple raster overlays (such as COGs or WMS layers) is added as data, only its first raster overlay is enabled by default; the others stay available in the theme but start off. Legend symbols and raster colour ramps are shown only while their layer checkbox is on. The Add data panel starts with groups collapsed and filters by group or layer name. Users can add an ArcGIS REST MapServer from the "Add your own layer" control. Each renderable sublayer is added separately using its service name, default visibility, and layer ID, within the selected group. Manually added MapServer layers are saved to browser `localStorage` and persist across sessions.

For example, Geomaterials currently uses `groups: ['Geology WMS']`. That named theme supplies its configured WMS overlay IDs to Geomaterials. Borehole depth and Quick Filters/Results Table remain Geomaterials-specific groups at the top of the layer panel.

The public profile's `config/style.json` supplies the MapLibre background style; configured raster and GeoJSON overlays provide its map content. Optional vector datasets can supply their own MapLibre style and PMTiles archive through `datasets`.

## Geomaterials JSON Data

Edit `config/config_geomaterials.js` to configure the Geomaterials theme. Each `tabs` entry specifies a JSON filename, its top-level `dataKey`, display name, and optional behavior. One tab is primary; its records provide the map geometry and IDs. Sibling records join to primary records by `linkField`.

The primary geometry is WKT in the configured projection. Valid borehole points are projected into WGS84 and rendered by MapLibre. On map movement, the current bounds scope the primary IDs; special filters and persistent column filters then intersect those IDs across datasets. Text/range filters use AND semantics, selected values within one dropdown use OR semantics, and the final intersected IDs drive the map and tables.

Useful per-deployment settings include:

- `dataDirectory`, `file`, and `dataKey` for the JSON locations and shapes.
- `dropdownColumns`, `rangeFilterColumns`, `hiddenColumns`, and `nonNumericColumns` for table filtering and presentation.
- `urlFields`, `computedLinks`, `urlBases`, and deployment link files for external destinations. Change `urlBases.sampleTrayImages` to set the production sample-tray image host.
- `popupFields`, `help`, `depthField`, and `depthClasses` for feature details, tab help, and map symbology.

Add a new data table by placing its JSON file under `data/geomaterials/` and adding a tab with the matching filename and top-level `dataKey`. Sibling tables need the same join field as the primary data.

## Results and Popups

The results panel is shared with vector query results. In the Geomaterials theme it adds dataset tabs, aligned column filters, sorting, exports, and shareable filter/map state. The Linked data eye controls the panel; changing filters or map bounds can reopen it. The panel is resizable.

Clicking a borehole opens configured primary details plus expandable sibling sections containing that borehole's currently filtered rows. Only one popup section stays expanded at a time; sections with multiple results have previous/next controls.

`js/map-feature-query.js` handles rendered-feature discovery, click/box geometries, and linked-record joins. `js/map-click-controller.js` coordinates click results from those queries and ArcGIS overlays, including JSON-theme geometry matches; it ignores stale asynchronous results and leaves notification picking and box-selection modes in control of their existing handlers.
